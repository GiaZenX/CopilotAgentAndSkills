## Highest-impact

### 1. Nested subagents are ALLOWED AGAIN by default — depth **3** (2.1.219, Jul 24). This REVERSES last week's item 2. The platform anti-nesting backstop is GONE; the kit's `guard_agent_spawn` + V14b `deny: Agent(project-manager)` is once again the ONLY thing stopping specialist fan-out
- **Source**: https://code.claude.com/docs/en/changelog — 2.1.219, July 24, 2026: *"Subagents can now
  spawn nested subagents up to depth 3 by default (was 1); set `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1`
  to disable nesting."* · seen 2026-07-31
- **What it is**: A straight reversal of the 2.1.217 change reported last week (item 2:
  *"Changed subagents to no longer spawn nested subagents by default"*). Six days later the default
  flipped the other way — nesting is re-enabled up to **depth 3**, opt-out via
  `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1`. (The per-session 200-spawn cap and the concurrent-20 cap
  remain, but those bound *volume*, not *nesting*.)
- **Why it matters here**: This lands squarely on the harness's **anti-re-delegation** invariant —
  the no-specialist-spawns-a-specialist rule enforced in prompt+hook via `guard_agent_spawn` and
  V14b `deny: Agent(project-manager)` (decided items `radar-0703-background-subagents` /
  `-agent-permission-rules`). Last week's report told you the runtime now enforced **zero nesting by
  default**, calling it "free defense-in-depth … a specialist fan-out loop is now blocked three ways."
  **That backstop is now gone** — the default permits depth-3 nesting again. The kit guard was
  correctly described last week as "still the semantic gate; the runtime caps are backstops," so
  **nothing in the kit is broken** — but the belt-and-suspenders margin the last two reports assumed
  no longer exists. Anyone who "hardened" by relaxing the kit guard on the assumption the runtime
  covers nesting would now have an open fan-out path.
- **Recommendation**: **adopt** — (a) **do NOT relax** `guard_agent_spawn` / the `deny: Agent(...)`
  rules; they are once again load-bearing, not redundant; (b) consider **pinning
  `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` in both kits' settings env** to deterministically restore
  the runtime backstop regardless of the shifting platform default (~20 min, settings `env` block —
  a user-approved edit; the watcher never edits it). · CC floor note: the default is **depth 3 as of
  2.1.219**; pin the env var if you want depth 1 independent of version. · **Status**: NEW ·
  **Material update to decided-area items** `radar-0703-background-subagents` /
  `radar-0703-agent-permission-rules`.
