### 2. `PreModelSwitch` / `PostModelSwitch` — a new deny-capable hook firing on model changes (2.1.251)
- **Source**: changelog https://code.claude.com/docs/en/changelog — 2.1.251 (Aug 28): *"Added
  `PreModelSwitch` and `PostModelSwitch` hook events (block, confirm, or annotate a model switch)"*;
  confirmed against the hooks reference (code.claude.com/docs/en/hooks): `PreModelSwitch` supports
  `permissionDecision: "deny"` / exit-code-2 to **block** the switch, matches on
  `canonical_to_model`, and receives `from_model`/`to_model`/`reason` (`user_requested` /
  `client_requested` / other); `PostModelSwitch` is async/log-only with the same fields · seen
  2026-09-04
- **What it is**: a hook pair on the model itself changing — before (blockable) and after
  (log-only), including model changes Claude Code makes on its own (e.g. restoring the model on
  resume).
- **Why it helps this repo**: none of the four existing gates (`gate_lead_write_scope`,
  `gate_spawn_needs_item`, `gate_commit_evidence`, `gate_todo_items` — all `PreToolUse`/`Bash`
  matchers) can see the model a role actually runs on changing. This is exactly the primitive
  `FR-0047`'s still-open half needs ("a silent fallback becomes visible" — request text, and §4 of
  the 09-02 measurement doc, "was noch fehlt, damit ein Pin-Fehler ein PROTOKOLLIERTES Ereignis
  wird"). A fifth gate on `PreModelSwitch` could deny any switch away from a role's own
  `model_tiers.yaml` pin; `PostModelSwitch` alone could log every switch into the same
  `project_memory/.audit` trail `notify_agent_events.py` already writes (accepted 2026-07-10).
- **Recommendation**: **adopt (propose — needs a DEC, not radar's to build)** — feed this to
  `FR-0047` as the concrete mechanism for its open half. Two things to confirm before designing
  against it (open questions, not yet measured): (a) whether it fires at all for a `Task`-tool
  subagent's *initial* model selection or only for a later change within a running session; (b)
  matcher/timing interaction with this repo's `agent:`-bound lead. ~2–3h research spike. ·
  **Status**: NEW

### 3. `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` — an opt-in env var that silently overrides every subagent's pinned model; its sibling was hardened the same week to respect per-role pins (2.1.251 / 2.1.257)
- **Source**: changelog https://code.claude.com/docs/en/changelog — 2.1.257 (Sep 1): *"Added
  `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` to apply `CLAUDE_CODE_SUBAGENT_MODEL` (or the main model) to
  every subagent, ignoring per-spawn and agent-definition model overrides"*; 2.1.251 (Aug 28):
  *"Changed `CLAUDE_CODE_SUBAGENT_MODEL` to set the default subagent model rather than override
  everything: an agent definition's `model:` and an explicit per-spawn model now take precedence
  over it"* · seen 2026-09-04
- **What it is**: two related env vars. The plain one, as of 2.1.251, now **respects** a role's own
  `model:` pin (good news — confirms this repo's frontmatter pins are the authority by default). The
  `_FORCE` variant, added 2.1.257, is the opposite: set it and **every** subagent — implementer,
  verifier, PM — runs on one model regardless of its `.md` frontmatter, with no error and nothing a
  gate would see.
- **Why it helps this repo**: this is a live, if opt-in, threat to the constitution's three-role
  separation ("Prüfer misst gegen den laufenden Code… der Sitzungsagent… urteilt nicht über ein
  Paket, das er selbst gebaut hat") that no gate here matches on (none reads env vars or the model
  actually used), and a distinct failure mode from item 1's now-measured 404-death: this path
  **succeeds silently on a different, valid model**, not an error.
- **Recommendation**: **watch / fold into `FR-0047`** — name it explicitly as a second way a role can
  run off-tier (the first, a broken pin, is now measured and closed per item 1). No kit-side fix
  exists for an env var set outside the repo; the realistic mitigation is detection (item 2), not
  prevention. ~15 min to add the reference to `FR-0047`. · **Status**: NEW
