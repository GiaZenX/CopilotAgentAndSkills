## Highest-impact

### 1. **Claude Code now has five hook types — `prompt` and `agent` (LLM-evaluated) join `command`/`http`/`mcp_tool` (official docs)** — this is the concrete mechanism the still-open `gate_subagent_output` → `SubagentStop` item was waiting for, and it is a source-format change (hook-registration schema) the Codex generator mirrors
- **Source**: Hooks reference https://code.claude.com/docs/en/hooks — a hook is `type: "command"`
  (shell), `type: "http"` (POST the event JSON to a URL), `type: "mcp_tool"` (call a connected MCP
  tool), **`type: "prompt"`** (single-turn Claude evaluation, returns a decision), or
  **`type: "agent"`** (spawns a subagent that may use Read/Grep/Glob to verify before returning a
  decision); `prompt`/`agent` hooks take a required `prompt` field and optional `model`, with
  `$ARGUMENTS` as the event-JSON placeholder · seen 2026-08-21. Community write-ups pair this
  directly with SubagentStop: *"every subagent should be paired with a SubagentStop hook that
  enforces non-negotiables before the lead folds a result back in"* (developersdigest.tech,
  hidekazu-konishi.com, claudefa.st) · seen 2026-08-21.
- **What it is**: Two new first-class hook types that let a hook's decision come from an LLM (a
  one-shot prompt) or from a tool-using subagent, instead of only a shell command's exit code.
- **Why it helps this repo**: The **2026-08-01 item 2** proposed moving `gate_subagent_output` to a
  per-agent `SubagentStop` frontmatter hook so a specialist's return is checked at the boundary
  rather than after the lead re-integrates it. Until now that meant a *command* hook. The `agent`
  hook type is a cleaner fit for the harness's verifier idea (a read-only Read/Grep/Glob pass over
  the returned package), and the `prompt` hook is a lightweight screen. **Caveat that the house
  rules force**: *"Eine Prüfung muss den Teil lesen, der läuft"* — a gate measures behaviour
  deterministically, not by a model's judgment. An LLM-judged `prompt`/`agent` hook is
  **non-deterministic** and cannot be the load-bearing gate; it can only *screen* ahead of a
  deterministic command hook. Adopt the pattern, keep the authority in a `command` hook.
- **Source-format duty**: hook registration schema is part of the neutral-source contract (agents
  `.md` frontmatter + `settings.json` hook blocks) that the Codex layer is generated from. New
  `type` values plus `prompt`/`model` fields are a **schema widening** — the generator and any
  schema check must accept them (or deliberately reject `prompt`/`agent` as Claude-only). Flag for
  the maintainer to confirm the generator doesn't choke on, or silently drop, a hook whose `type`
  it doesn't know.
- **Recommendation**: **adopt (evaluate)** — prototype the SubagentStop refactor as a `command`
  hook (deterministic authority) with an optional `agent`-hook screen in front; bake the
  termination-condition guard in from the start (last week's caveat: a blocking SubagentStop with
  no marker-file/bounded-retry loops forever). Separately, confirm the Codex generator's treatment
  of the two new `type`s. ~2–3 h combined. · **Status**: NEW

### 2. **"Default teammate model" setting removed (2.1.234): agent-team teammates now use the leader's model unless the spawn names one** — lands on the kits' per-role model pinning (`model_tiers.yaml` / `model_map`); audited this week and currently SAFE
- **Source**: changelog https://code.claude.com/docs/en/changelog — 2.1.234 (Aug 17): *"Removed the
  'Default teammate model' setting from `/config`; agent-team teammates now use the leader's model
  unless the spawn names one"* · seen 2026-08-21
- **What it is**: The global fallback that gave every un-pinned teammate a fixed default model is
  gone. A spawned teammate that doesn't name a model now **inherits the leader's model**.
- **Why it helps this repo**: The kits tier every role by frontmatter (`worker`/`lead`/`fable` via
  `model_tiers.yaml`). If any spawnable role lacked a `model:`, it would now silently ride the
  lead's tier — expensive (lead is `opus`/`fable`) or simply wrong. **I audited it read-only this
  week: every kit specialist role and both writing harness roles pin `model:` explicitly** —
  `grep -rn '^model:' team-kits/*/agents/ .claude/agents/` shows all of dev/office/research roles
  on `worker`/`lead`/`fable`, `harness-implementer`/`harness-verifier` on `opus`, the watchers on
  `sonnet`. So **no silent inheritance today.** Same grep also confirms **no role uses
  `subagent_type: "fork"`** — which closes the grep last week's item 2 asked for.
- **Recommendation**: **adopt (cheap hardening)** — add a structural test asserting every spawnable
  role `.md` carries a `model:` line (a both-ends tripwire per house rules), so a future role added
  without one can't silently inherit the lead's tier once the platform default is gone. The audit
  passes now; the test keeps it passing. ~30 min. · **Status**: NEW

### 3. **Auto-mode git-status integrity fix (2.1.236): `status.showUntrackedFiles=no` can no longer fool the clean-tree check** — same bypass class as `gate_commit_evidence`'s working-tree diff-hash, worth a measured check
- **Source**: changelog https://code.claude.com/docs/en/changelog — 2.1.236 (Aug 19): *"Improved
  auto mode: the git status check can no longer be fooled by a repo's `status.showUntrackedFiles=no`
  setting into reporting a clean tree"* · seen 2026-08-21
- **What it is**: A repo-local git config (`status.showUntrackedFiles=no`) made `git status` hide
  untracked files, so Claude Code's auto-mode read a dirty tree as clean. Now fixed in CC's own
  checker.
- **Why it helps this repo**: `gate_commit_evidence.py` only lets `git commit` through when an
  active `EVD` names the **diff-hash of the working tree**. If that hash is computed from a git
  view that a repo-local setting (or a bare `git diff` that ignores untracked files) can **shrink**,
  a **new, untracked** file could ride into the commit uncovered by the evidence — the same
  "checker sees less than the operation does" family as H19/H20/H33 and last week's item 4. I
  grepped the hook set for untracked-file handling (`untracked`, `--porcelain`, `ls-files`,
  `git diff`) and found **no explicit handling** — which means this is a **vector to measure, not a
  confirmed hole**: the diff-hash's exact input (does it include untracked/staged-but-new files?)
  needs to be read off the code that computes it.
- **Recommendation**: **adopt (evaluate)** — reproduce in a throwaway clone outside the repo: create
  an untracked file, compute the EVD diff-hash, and check whether the gate's hash changes. If it
  doesn't, an untracked file commits without evidence → record it as a measured hole in
  `docs/POST_V2_WISHLIST.md` with the chain; if it does, note the gate already covers this class.
  ~1–1.5 h. · **Status**: NEW

### 4. **MCP/plugin config now gated behind folder trust + stripped of inherited credentials (2.1.238), and a plugin catalog entry can run a `headersHelper` command on install** — reinforces the workspace-trust install note and adds a new plugin-distribution surface
- **Source**: changelog https://code.claude.com/docs/en/changelog — 2.1.238 (Aug 20): *"MCP
  `headersHelper` in a project `.mcp.json`, and inline MCP servers in project or `--add-dir` agent
  files, now require that folder's trust dialog to have been accepted (also under `claude -p`)"* ·
  *"MCP `headersHelper` from a project `.mcp.json`, plugin, or agent file runs without inherited
  credential env vars"* · *"Plugin marketplaces: `headersHelper` … runs a command that mints HTTP
  headers … A catalog entry's `headersHelper` runs only when you install or update that plugin,
  after its command is shown; `claude plugin install/update` ask `[y/N]`"* · seen 2026-08-21
- **What it is**: Two hardening changes (project MCP config now needs an accepted trust dialog even
  under `-p`; header-minting helpers no longer inherit the session's credential env) plus one new
  capability (a marketplace/catalog entry can run a shell command at install/update to mint auth
  headers, shown and `[y/N]`-gated).
- **Why it helps this repo**: The **2026-08-01 item 3** workspace-trust note — project-level
  `.claude/` hooks are silently skipped in an untrusted folder — only gets more load-bearing:
  `-p`/headless runs (which is how the watchers and any CI-style invocation execute) now also need
  the trust dialog for project MCP config. The kits ship as **source** and declare no
  `headersHelper`, so **no kit exposure today**; but if the kits are ever distributed via a `url`
  marketplace, the catalog `headersHelper` is a new **install-time command-execution** surface to
  reason about before publishing.
- **Recommendation**: **watch / fold into the workspace-trust note** — add "project MCP config and
  inline MCP servers require an accepted trust dialog, including under `claude -p`" to the same
  CC-floor/install note, and record the catalog-`headersHelper` execution surface as a
  pre-publish checklist item for the day a kit ships through a marketplace. ~20 min. · **Status**: NEW
