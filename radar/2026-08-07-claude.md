## Highest-impact

### 1. A cluster of Bash/PowerShell **permission-parser bypass** fixes (2.1.221–2.1.223) — same evasion class as the harness's own command-line gates; free adversarial corpus for `gate_lead_write_scope` / `gate_commit_evidence`
- **Source**: changelog https://code.claude.com/docs/en/changelog —
  **2.1.221** (Aug 4): *"Fixed a Bash tool permission-check bypass where zsh could execute hidden
  commands in `[[ ]]` regex conditionals"* · *"Fixed PowerShell permission checks mishandling paths
  containing quote characters on Windows; such paths now prompt for approval"*;
  **2.1.223** (Aug 6): *"Fixed a Bash permission bypass where a crafted command could hide parts of
  itself from permission checks"* · *"Fixed permission prompts so commands padded with tabs or
  invisible Unicode can no longer hide part of the command from the approval dialog"* · seen 2026-08-07
- **What it is**: Four platform fixes in one window, all the same shape — a shell command line crafted
  so a **parser** sees less than the shell executes (zsh `[[ ]]` conditionals, quote characters in
  paths, tab/invisible-Unicode padding, "hide parts of itself").
- **Why it helps this repo**: This is *exactly* the terrain `gate_lead_write_scope`,
  `gate_commit_evidence` and `_harness.command_line` (`.claude/hooks/_harness.py:1463`) operate on —
  they tokenize a shell command line to decide write-scope and commit-evidence. The repo already tracks
  holes in this precise family: **H32/H34** (a quoted span behind a flag-write the kit tokenizer strips
  as prose), **H33** (tilde prefixes, DEC-0020), and the 2026-08-07 command-substitution work
  (`echo $(sed -i …)`, `_harness.py:1469`). Anthropic independently found and fixed the **same evasion
  class** in its own Bash/PowerShell permission checker — that is (a) a strong validation signal that
  the harness's blind-spot list is the right list, and (b) four concrete, reproducible attack strings
  the harness can lift straight into `test_gates.py` as vectors. Note the seam: these fixes harden
  Claude Code's **built-in** Bash permission check, **not** the kit gates — so they do **not** close the
  kit's H32/H33/H34 holes for free; they map the terrain and hand you test cases.
- **Recommendation**: **adopt (evaluate)** — mine the four cases (zsh `[[ ]]`, quoted-char paths,
  tab/invisible-Unicode padding, "hidden parts") as new `gate_lead_write_scope`/`gate_commit_evidence`
  vectors; where the kit tokenizer under-reads, record it as a measured hole in
  `docs/POST_V2_WISHLIST.md` rather than claiming coverage. ~1–2 h. · **Status**: NEW

### 2. **PreToolUse auto-allow hooks bypassing tool restrictions in background agent tasks — FIXED (2.1.222)** — sets a hard CC floor under the harness's entire enforcement model
- **Source**: changelog https://code.claude.com/docs/en/changelog — 2.1.222 (Aug 4): *"Fixed PreToolUse
  auto-allow hooks bypassing tool restrictions in background agent tasks (summaries, compaction,
  renames)"* · seen 2026-08-07
- **What it is**: Before 2.1.222, a PreToolUse hook that auto-allows could let a background agent task
  (summary/compaction/rename) run a tool that restrictions should have blocked.
- **Why it helps this repo**: **Every** one of the harness's four gates is a `PreToolUse` hook. This fix
  means the gates' guarantees only hold in background/summary/compaction contexts at **CC ≥ 2.1.222**;
  on an older client a background task could slip a write past `gate_lead_write_scope` /
  `gate_commit_evidence`. That's a concrete floor for the enforcement story, not a cosmetic note.
- **Recommendation**: **adopt** — add a one-line CC-floor note to the install docs / `HARNESS_LOG`
  ("the four gates rely on PreToolUse firing in background tasks; require CC ≥ 2.1.222"). ~15 min. ·
  **Status**: NEW

### 3. **Worktree isolation now covers file edits + Bash in every session type; isolated subagents can no longer run destructive git against the main checkout (2.1.222)** — hardens the `harness-verifier` "read-only copy outside the repo" model
- **Source**: changelog https://code.claude.com/docs/en/changelog — 2.1.222 (Aug 4): *"Fixed
  worktree-isolated sessions and their subagents being able to run destructive git commands against the
  main checkout; isolation now applies to file edits and Bash in every session type"* · seen 2026-08-07
- **What it is**: Worktree isolation used to leak — an isolated session/subagent could still hit the main
  checkout via Bash/git. Now isolation covers file edits and Bash uniformly.
- **Why it helps this repo**: The constitution requires the **Prüfer/`harness-verifier`** to work
  "read-only in a copy **outside** the repo," and CLAUDE.md's parallel-write rules exist precisely
  because a stray write reaches the shared tree. This platform fix is the runtime backstop for that
  discipline — and it is directly the failure mode I hit this run (a test's ground-truth shell writing
  the live tree). If the kits adopt worktree isolation for the verifier, **CC ≥ 2.1.222** is the floor
  where it's actually airtight.
- **Recommendation**: **watch** (adopt the CC-floor note if/when the verifier moves to worktree
  isolation). ~10 min for the note. · **Status**: NEW
