### 2. Subagents no longer spawn nested subagents by default (2.1.217) + concurrent-spawn cap (default 20) — the anti-re-delegation invariant is now the platform DEFAULT
- **Source**: https://code.claude.com/docs/en/changelog — 2.1.217, July 21, 2026 · seen 2026-07-24
- **What it is**: *"Changed subagents to no longer spawn nested subagents by default; set
  `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` to allow deeper nesting."* Plus *"Added a cap on
  concurrently-running subagents (default 20, override with `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`)
  so one message can't fan out unbounded background agents"* and *"`--max-budget-usd` … once the cap
  is reached, new spawns are denied and running background agents are halted."*
- **Why it matters here**: This lands precisely on the harness's **anti-re-delegation** invariant —
  today enforced in prompt+hook via `guard_agent_spawn` + V14b `deny: Agent(project-manager)` (the
  no-specialist-spawns-a-specialist rule). The platform now enforces **zero nesting by default** at
  the runtime layer, and adds a **concurrent** ceiling (20) to complement the **per-session total**
  cap (200, from 2.1.212, item 2 last week). A specialist fan-out loop is now blocked three ways:
  kit prompt, kit hook, and two runtime caps. Free defense-in-depth; no kit change required. Confirms
  the design — record so nobody "hardens" by loosening the kit guard on the assumption the runtime
  now covers it (the kit guard is still the semantic gate; the runtime caps are backstops).
- **Recommendation**: **ignore (confirms design)** · optional: note `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`
  (leave at 0/default) and `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` in the orchestration docs as
  belt-and-suspenders knobs (~15 min if adopted). · CC floor note: **≥ 2.1.217** for the default. ·
  **Status**: NEW

## Latent-CI item — ruff is unpinned in CI; a runner that pulls ruff ≥ 0.16 will go red on 913 default-rule findings
- **Source**: repo `.github/workflows/ci.yml` (`pip install --upgrade … ruff …` then `ruff check
  team-kits tools`) + local repro (ruff 0.6.9 → pass; ruff 0.16.0 → 913 findings) · seen 2026-07-24
- **What it is**: CI installs ruff **unpinned/`--upgrade`**. ruff's default ruleset broadened
  substantially between the repo's era (0.6.x) and current (0.16.x), so the *same* clean tree now
  trips 900+ new-default lints (UP/BLE/S/SIM/DTZ/EXE/FURB/…). This is a **toolchain-version** issue,
  not repo drift — but because the pin is floating, the next CI run on a fresh runner image could
  flip the lint gate red with no code change.
- **Why it matters here**: `ruff check` is a repo quality gate (CI + the watcher health line). A
  floating pin means the gate's verdict is non-reproducible across runner images.
- **Recommendation**: **adopt** — pin ruff in CI (and optionally add an explicit `[lint] select`
  to `ruff.toml` so intent is version-independent), OR consciously adopt the newer defaults and
  clean/`# noqa` the 913. Either is a real decision, not an auto-fix — flagging, not touching. ~30 min
  to pin; larger if adopting the new ruleset. · **Status**: NEW

### 5. exit-2 hooks whose stdout JSON fails schema validation were not blocking — fixed (2.1.214). Harness has NO exposure: its gates block via exit-2 + STDERR text, not stdout JSON
- **Source**: https://code.claude.com/docs/en/changelog — 2.1.214, July 18, 2026
  (*"Fixed hooks with exit code 2 not blocking as documented when the hook's stdout JSON fails
  schema validation"*) · seen 2026-07-24
- **What/why**: This is the exact enforcement primitive every kit gate uses. I checked how the gates
  emit a block: `gate_git.py` (and the family) write the reason to **`sys.stderr`** and `sys.exit(2)`
  — **plain text, no stdout JSON**. The only kit hooks that emit stdout JSON (`hookSpecificOutput`/
  `json.dumps`) are the non-blocking status/audit hooks (`session_status`, `notify_agent_events`,
  `_audit`, `_compat`), which don't gate. So the now-fixed bug (stdout-JSON-schema-failure dropping
  an exit-2) **could never have dropped a kit gate** — the stderr+exit-2 pattern is precisely the
  safe path. Confirms design; record so nobody "improves" a gate by adding stdout JSON to it.
- **Recommendation**: **ignore (no exposure; confirms stderr+exit-2 design)** · CC floor note
  **≥ 2.1.214** for anyone who *does* emit stdout JSON from a blocking hook. · **Status**: NEW
