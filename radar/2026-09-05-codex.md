## Source-format scan (standing duty)

- **No new per-agent TOML field this round that the `codex:` overlay cannot already carry** — item 5
  confirms `sandbox_mode` and "other config.toml keys" are reachable as arbitrary overlay scalars
  today, no schema step needed.
- **One genuine gap surfaced**: `Interrupt` (item 4) is a Codex-only lifecycle event with no Claude
  Code equivalent, and the source format's only Codex-specific escape hatch
  (`codex:` agent-frontmatter overlay) operates at the per-agent-TOML level, not at the
  `settings.json`/`hooks.json` registration level — there is no sanctioned way today for a kit source
  to register a Codex-only hook event at all, Claude-equivalent or not. No kit needs this today (none
  registers anything Interrupt-shaped), so **not** a trigger for the neutral-source-format trip-wire
  by itself, but the first concrete example of the *kind* of gap that trip-wire (HARNESS_LOG
  2026-07-14) is watching for on the hooks side specifically, as opposed to the frontmatter-field side
  the overlay already covers.
- **Reasoning-effort vocabulary discrepancy** (item 3) is a source-format-adjacent question too:
  today's kit sources may carry `effort:`/`model_reasoning_effort:` values `low|medium|high|xhigh|max`
  per `model_tiers.yaml`'s own documented shared vocabulary (line 42) — `ultra` was never added to
  that shared list, only mentioned in a comment as a Codex-only value routed through the overlay. If
  the spike in item 3 confirms `ultra` is real and Codex-only, no schema change is needed (the overlay
  already covers exactly this case); if it confirms `ultra` does not exist as a per-call value at all,
  the comment should simply be removed. Either resolution is cheap; what is not cheap is answering it
  from documents that disagree with each other.
