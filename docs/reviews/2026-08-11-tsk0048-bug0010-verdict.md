# TSK-0048 (BUG-0010 / DEC-0038 AC-1) — Verifier verdict: lease honesty, 2026-08-11

## The decision (DEC-0038, AC-1)
A lease-bearing status is not reachable by a bare `transition` when no lease is in force; sweep-leases
reports a LEASED-without-lease rather than silently resetting it. No parallel non-dispatch completion
path invented.

## Attacks, all measured
- **Dispatch NOT broken (critical):** the real lease path reaches the statuses —
  `create_lease` → LEASED, `spawn_outcome(ok)` → IN_PROGRESS — both writing `task["status"]` directly
  (`dispatch.py:207/709`), never through `state.transition`. The guard sits only in
  `_transition_locked` (`state.py:1055-1056`), so it does not disable dispatch. No regress.
- **Refusal holds, both statuses, bound to the property:** bare READY→LEASED and LEASED→IN_PROGRESS
  without a live lease → DispatchError, status unchanged. The guard tests `to_status not in
  LEASE_BEARING_STATUSES` (a model tuple, not a single name); both ends hit. No overlooked entry:
  the only transition entry is `transition→_transition_locked`; LEASED/IN_PROGRESS exist only in the
  TSK automaton; no other direct writer (initial/invalidation-target) can produce a lease-bearing
  status. Tripwire `test_the_lease_bearing_statuses_are_the_ones_the_lifecycle_produces` runs the
  live lifecycle and reads the statuses off it → "one short" goes red.
- **sweep report, both ends:** LEASED-without-lease → reported by id, status stays LEASED (no silent
  reset); IN_PROGRESS-without-lease → not reported (legitimate, a running child outlives its lease);
  a real expired LEASED-with-lease → still swept to READY (core sweep intact). CLI prints the third
  line.
- **`lease_in_force`** means live AND unexpired (`_expired`): with an expired lease, bare
  transition→IN_PROGRESS is refused — not too weak.
- **Backward-compat:** validate against the project_memory copy → 0 errors / 0 warnings; no legitimate
  transition broken.
- **`drive_task_to` helper** uses the real lease lifecycle (create_lease/spawn_outcome, mints a scope
  approval at the root) — no hand-written lease shortcut, so the 5 migrated tests still measure.
- **Named residue check:** `migration_writable_statuses("TSK")` still lists LEASED/IN_PROGRESS
  (reachability walk) but migration writes archive records directly, never mapping to them;
  `test_no_direct_status_write...` scans all kernel modules incl. dispatch.py and binds create_lease's
  write via LEASE_MINTED_STATUS. Self-defects found+fixed during build (AST reader, backtick comment).
- **Red-without-fix reproduced:** guard removed → `test_a_bare_transition_cannot_mint_leased` fails;
  reporter → [] → the two sweep tests fail; dispatch.py restored byte-identical after.

## Optional hardening (non-blocking, not a hole, not in the hole list)
The tripwire measures only one end (lifecycle-produced statuses are IN the tuple, catching "one
short") but not that the tuple has no EXTRA status. An over-inclusive entry would over-refuse (not a
security hole — over-refusal, would surface elsewhere). Recommended future one-line addition:
`set(LEASE_BEARING_STATUSES) <= {statuses observed in the run}`. To be folded into the next kernel
round that touches test_kernel.py.
