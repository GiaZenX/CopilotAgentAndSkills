The real root of BUG-0020, discovered via the .claude handback: `rm -f "quoted canonical path"` was
rc 0 because the kit gate's `_MESSAGE_ARG_RX` (IGNORECASE, alternative contains `-F` → matches `-f`)

## Part A — the fix (kit code): PASS
`_MESSAGE_ARG_RX` is now a verb-bound `_VerbBoundMessageRemoval` (same `.sub(" ", text)` interface):
it empties the quoted span only when the verb actually takes a message (`_PROSE_MESSAGE_VERBS = {gh,
hub, glab}`, git in `{commit, tag, merge, notes, stash}`). After rm/cp/mv/Remove-Item/git rm the
quoted operand stays the file → refused.
- Hole closed, file effect measured (bash arbiter): `rm -f/-F/-rf "protected"`, `mv`, `cp -b`,
  `Remove-Item`, `git rm`, `truncate`, `install`, `dd of=`, `tee`, `Set-Content`, flag-after → all
  rc 2, file untouched. Red-without-fix: root reverted to plain regex → `rm -f "…DEC-0001.yaml"`
  rc 0, file GONE.
- No new hole at the verb seam: `git mv`, `git stash --`, `git rm -F`, flag-after all rc 2. `git
  stash -F "path"` empties the span (stash is a message verb) but is harmless — git itself rejects
  `-F` for stash (rc 129), file intact; no file-destroying git verb is in the message set.
- No functional over-refusal: `git commit/tag/merge/notes -m "…protected…"`, `gh --body`, `echo`,
  `rm -f "docs/tmp.txt"` all rc 0. Quote-aware segment boundary: `git commit -m "x" && rm -f
  "…DEC-0001.yaml"` → rc 2 (only the commit message emptied).
- Mirror byte-identical across 3 kits; `tools/test_hooks_v2.py` red-without-fix proven; kits
  2026.08.11-5.
