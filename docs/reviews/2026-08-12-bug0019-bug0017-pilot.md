## BUG-0019 (primary) — phase-2 PM transcript dependency: **FAIL** (spec "0 active transcript dependencies" violated)

The transcript reach **persists but shrank**. Phase 2, turn 0, measured `use`-event order:
1. `Read` `project_memory/generated/session_brief.yaml`
2. `Read` `project_memory/product/masterplan.md`
3. `Read` `project_memory/product/active/PR-0001.yaml`
4. **then** `~/.claude/projects/…/8609861d-….jsonl` — **3 accesses** (`wc -l`; last 15 lines parsed;
   last 30 lines parsed).

- **vs. prior baseline** (`vokabeltrainer-phase2.jsonl`, same method): **6 accesses**. → **6 → 3.**
- **AC-1 met.** The PM handed over correctly WITHOUT depending on the transcript for function: first
  say-line summarised masterplan + PR-0001, did not start from zero.
- **AC-2 measured — what the brief lacks:** the PM read the transcript **tail** because the brief does
  not carry the **last conversation state** — that in session 1 an approval had already been requested
  and answered "Freigeben", and that the /hooks situation was open. The PM's own opening proves it:
  "In der letzten Session hattest du die Freigabe für den Scope bereits mit 'Freigeben' beantwortet —
  aber technisch kam sie nicht an." That fact lives ONLY in the transcript; the brief had
  `active_roots:[PR-0001]`, `standing_decisions:[]`.
- **AC-3 distinguished:** handover did NOT functionally fail — the transcript was **supplementary
  reading**. Brief + masterplan + root item were read first and sufficed.
- **HONEST CONFOUND:** `standing_decisions` was **empty** (a fresh auto-init makes no DEC, only
  PR-0001). So TSK-0051's "decisions in the brief" had **nothing to carry** in this handover and
  **cannot** be credited for the 6→3 shrink; the cross-run comparison (different ideas, model variance)
  is not cleanly isolated. The only solid claim: **the raw-transcript reach persists**, for exactly what
  TSK-0051 does NOT address — the **last turn / approval state**, not the standing decisions.

**Mechanism:** the missing "last-round / pending-approval context" in `session_brief.yaml`. While the
brief does not carry the last turn's state (open/answered approval, last user wording), the PM recovers
it from `~/.claude/projects/*.jsonl`.

## BUG-0017 (secondary) — approval/mint path in the SDK: **FAIL for phase 1**, but the original hypothesis is partly REFUTED

- **Phase 1 (entry session): AC-2 VIOLATED.** The entry agent **invents the /hooks ceremony** (turn 4):
  "Bitte führe `/hooks` aus, um das neue Hook-Bundle dieses Projekts zu bestätigen … die Freigabe ist
  technisch noch nicht 'geprägt'," with an invented system status `hook_trust: unverified`,
  `restart_required`, aimed at a non-technical persona. Exact BUG-0017 reproduction.
- **Phase 2 (restart PM): CLEAN MINT.** The PM ran `request-approval scope PR-0001`, posed a
  **structured** AskUserQuestion with `[APR-REQ:a507a615…]` / option "Freigeben [5acc16]", the answer
  arrived via `can_use_tool` → **approval minted**: `approvals/APR-0001.yaml` (`mint_code: 5acc16`,
  `subject_manifest_hash: 9c880d40…`), PR-0001 `status: APPROVED`, `approval_ref: APR-0001`. Only ONE
  "hooks" mention in phase 2, a harmless `Read` — no ceremony.
- **The decisive new measurement:** the mint path **works over the SDK** — once the session starts with
  hooks already installed. The BUG-0017 `observed` claim ("the structural identity of an
  AskUserQuestion answer does not arrive in the SDK") is **REFUTED**: the identity arrived, the approval
  minted. The defect is **confined to the entry session**, whose freshly-installed hooks are not yet
  active — the **same root as BUG-0016**. The phase-2 PM even self-diagnoses this correctly.
- **AC-3:** interactive CLI not measurable headless — stays open. But "pure SDK limit" does NOT hold:
  the SDK CAN mint. It is a **session-lifecycle** problem (entry session), reproduced in the SDK.

**Fix anchor (different from the item's claim):** not "the SDK cannot mint," but "the entry session
does not mint because its just-installed hooks are not active, and the agent rationalises that as a
/hooks requirement." Approval works cleanly **after restart** — the step the model already demands.

## The convergence — one root, one fix closes both (and ties to BUG-0016)

Both findings share the entry-session-hooks-inactive root, and one change closes both:

> When the entry session reaches the restart boundary, it must record the **pending-approval /
> handover context** into **canonical state** (an item field or a brief field) — not into the chat log,
> and not into an invented ceremony.

Then (a) the entry agent stops inventing a /hooks ceremony and instead honestly states "the scope
approval is minted in the next session, after restart" (BUG-0017 AC-2), and (b) the phase-2 PM reads
that pending-approval / last-turn context from the brief instead of the transcript (BUG-0019 AC-2). The
durable state carries the handover, which is the whole design intent.
