## Verdict: STATIC PASS — committable. Behavioural confirmation still needs a live phase-1 pilot.

The entry session's /hooks hallucination was traced (EVD-0020) to the guard ALLOWING the scope-approval
AskUserQuestion: the entry agent posed it, the mint failed (kit hooks inactive), and it rationalised
/hooks. The fix makes the always-active global guard (`user/claude/hooks/handover_guard.py`,

so the flow never starts and the agent gets an honest "approval after restart; do NOT run /hooks".

## The make-or-break check: the guard's marker matches the REAL emitter — PASS
The guard keys on `_APR_REQUEST_MARKER = re.compile(r"\[APR-REQ:")`. The kernel emits it in
`team-kits/kernel/approvals.py:692` as `[APR-REQ:<id>]`; the kit reads it in
`gate_approval.py:52` as `\[APR-REQ:([0-9a-f]{32})\]`. Byte-exact match (brackets, colon, case). The
marker survives `json.dumps` unescaped. The fix is NOT inert — it hits exactly the token the approval
flow emits (verified against the real emitter, not the test fixture).
