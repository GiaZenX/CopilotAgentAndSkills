# H154 -- Die Migrationstuer schreibt einen Endzustand ohne die Evidenz, die die Kante verlangt (neu, TSK-0122)

**Mechanismus.** `state.capture_migrated_hole` schreibt einen Loch-Datensatz direkt in den Status,
den sein Urteil schon hatte. Fuer ein geschlossenes Loch ist das `VERIFIED` — ein Status, den die
gewoehnliche Kante nur mit einer nutzergeminteten Freigabe UND einer bestandenen Test-Evidenz
erreicht (`state._assert_confirmed`, `approvals.APPROVAL_TRANSITIONS`). Die Tuer geht an beidem
vorbei.

**Kette (gemessen), 2026-09-04 gegen eine Kopie des Repos ausserhalb davon:**
`state.migration_writable_statuses("BUG")` erreicht `VERIFIED` NICHT — die Scope-Freigabe steht
davor. Rund die Haelfte der Eintraege dieser Liste traegt aber genau dieses Urteil, also waere die
Migration ohne diese Tuer je Eintrag eine nutzergemintete Freigabe und ein Evidenz-Datensatz —
eine Frage je Eintrag, ueber ein Dokument, das der Nutzer bereits einmal beurteilt hat.

**Urteil: offen, gemessen, bewusst nicht geschlossen (DEC-0073 (3a), Nutzerentscheidung
2026-09-04).**

**Was stattdessen begrenzt** — vier Bolzen, als das geschrieben, was der Code PRUEFT: die Tuer
nimmt nur einen Koerper mit `hole_number` (ein Feld, das `capture` einem Aufrufer verweigert); nur
einen Status, den der Automat des Typs wirklich hat; einen terminalen Status ausschliesslich in den
ARCHIVBAUM, wo `report.validate_state` nicht urteilt und kein Gate eine Autorisierung liest; und
eine bereits vergebene Nummer wird ZURUECKGEGEBEN statt ueberschrieben. Gemessen an einer Kopie des Repos: jeder
Eintrag der Liste in einem Lauf, zweiter Lauf rc 0 unter einer Sekunde ohne eine Aenderung,
Dokument byte-identisch, `validate` danach ohne einen einzigen zusaetzlichen Befund. Rot ohne den Fix:
`tools/test_state.py::test_the_migration_door_writes_a_hole_and_refuses_everything_else`.

**Zweite Restklasse derselben Leseseite, gemessen 2026-09-05 (Pruefung Runde 1, F20).**
`state._iter_every_stored_item` schluckt eine Leseausnahme, damit ein einzelnes kaputtes
Item keinen Leser stillegt. Der Preis: ein Loch-Item mit zerstoertem YAML verschwindet lautlos
aus allen drei Pruefern — gemessen an H156, `.claude/hooks/test_gates.py::test_every_hole_states_a_verdict_and_an_unclosed_one_names_its_limit` bleibt rc 0. Fuer ein AKTIVES Item meldet `report.validate_state` die
unlesbare Datei; fuer ein ARCHIVIERTES meldet es niemand, weil der Validator die aktiven Items
beurteilt. **Was stattdessen begrenzt:** die Datei liegt unter git, ihr Verschwinden aus dem
generierten Index ist ein Diff, und der Index wird aus dem SPEICHER regeneriert — beim naechsten
`--reindex` faellt die fehlende Zeile auf. Nicht begrenzt: die Zeitspanne dazwischen.
