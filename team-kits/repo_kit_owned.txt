# Repo-template scripts the SCAFFOLD OWNS: it overwrites them on every run (like the hooks) instead
# of keeping a project's copy, so a kit fix to one of them reaches every installed project and none
# of them ever lands on .claude/kit_update_pending.repo. Read by BOTH scaffold twins
# (scaffold_team.sh / scaffold_team.ps1), so the two lists cannot drift. A line no kit ships any
# more is a line that silently stopped delivering, which is why both ends of this list are read
# against the templates the kits actually carry, in
# tools/test_kitupdate.py::test_every_kit_owned_path_is_shipped_by_some_kit.
#
# WHY A FILE MUST BE HERE is a PROPERTY, not a taste: a repo script the enforcement layer refuses
# in-session writes to (guard_harness_selfmod.BLOCKED_REPO_PATHS -- the ledger judge, the entry
# point) can receive a kit fix by NO other route. The PM may not merge it, and leaving it
# copy-if-absent kept the project's forked copy forever while the pending list handed the
# non-developer user `cp` lines for the one file nobody in the session may write (BUG-0068). So
# every guarded repo script is owned here. harness.py and the kit-check tooling are owned for the
# neighbouring reason -- they are the entry point and the checks every fail-closed remedy runs.
#
# einvoice_extract.py is owned for a THIRD reason, and this one is a judgement rather than a
# property a test can read: it turns a supplier's document into the money figure that gets booked,
# so a project's forked copy is a second money parser nobody reviews, and a wrong figure it
# returns is spent money. It shipped one (BUG-0072). The pending list would deliver the fix to a
# PM who must still act: measured 2026-08-29 on the real office project, that list held 7 entries
# nobody had worked through.
#
# A file NOT here is copy-if-absent: the project may customise it, and the pending list reports a
# real content divergence (line-ending style ignored) for the PM to work through the normal loop.
# The price of a line here is the other direction: the scaffold overwrites a project's own changes
# to that file without asking, which is why the list stays short and each entry says why.
#
# The invariant "every guarded repo script is owned here" is pinned against the running guard by
# tools/test_kitupdate.py::test_every_guarded_repo_template_is_refreshed_by_the_scaffold; add a
# guarded repo path without a line here and that test goes red.
